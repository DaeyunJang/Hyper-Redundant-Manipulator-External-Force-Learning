# F/T 누락과 학습 윈도우 점검

2026-09-28 사용자 질문: 수집 도중 set zero를 누르면 F/T가 누락되는데 학습에서는 어떻게 처리하는가.
현재 파일을 읽기 전용으로 점검했다. 학습/라벨/원본 변경은 수행하지 않았다.

## 현재 구현 동작

- 기본 force_source=kalman이며 fts_kalman.aligned_fx/fy/fz가 정답이다.
- 선택 입력과 정답 XYZ의 빈칸/NaN/Inf/비수치, 필요한 matched 또는 aligned_force_valid가
  True가 아닌 행, ±25ms 초과/결측 시간차, hrm_base가 아닌 frame은 유효 행에서 제외한다.
- 누락을 숫자0이나 무부하 라벨로 채우지 않고 보간/직전값 복사도 하지 않는다.
- 유효성은 입력과 정답을 함께 고려한다. F/T 정답이 누락된 행은 현재 공동학습의
  힘/하중/위치 샘플 전체에서 제외된다. 위치 학습에만 별도로 재사용하는 구현은 없다.
- 원래 행 번호를 유지하며 invalid 행이 하나라도 있으면 연속 윈도우 카운트를 초기화한다.
  기본30행 모두 정상인 창부터 다시 사용한다. 약30Hz이면 정상 복구 후 약1초 분량이며
  이는 연속 유효 입력 길이 조건이지 필터 안정화를 측정했다는 뜻이 아니다.
- CSV 행 자체가 빠졌어도 타임스탬프가 비증가하거나 간격이 중앙값×1.5를 넘으면
  윈도우를 끊는다. 세션 간 창도 만들지 않는다.
- 현재 Kalman 선택에서는 raw F/T만 누락되고 Kalman과 선택 입력이 유효하면 제외하지
  않는다. Kalman이 누락되면 raw로 자동 대체하지 않는다.

## set zero 자체를 인식하는가

현재 loader에는 set-zero 이벤트 처리, 이벤트 전후 별도 안정화 구간 제외, 영점 변화량
교정이 없다. 검사한 CSV 헤더에 zero/tare/calib 이름의 이벤트 열도 없었다.
따라서 관측한 결측의 원인을 set zero로 단정하지 않는다. 녹화 밖의 이벤트 로그나
센서 프로그램 동작을 이번 검사에서 확인하지 않았다.

재설정 중이거나 복구 직후에도 정상 숫자와 True flag/허용 시간차가 들어오면 현재
조건을 통과할 수 있다. 숫자0은 정상 측정값일 수 있어 0이라는 이유로 제거하지 않는다.
오래된 값도 매칭 시간차 검사 범위 밖이면 거절되지만, timestamp/flag가 정상으로 저장된
경우 값이 실제 최신 측정인지까지 이 로더가 증명하지 못한다.

향후 명시적인 set-zero 시작/종료 시각을 기록하면 그 이벤트를 기준으로 구간을 끊고
안정화 구간을 추가 제외할 수 있다. 제외 길이를 임의로 정하지 않고 기록을 보고 결정한다.
이번에는 그런 정책을 새로 적용하지 않았다.

현재의 invalid행 및 해당행을포함한시계열창제외 규칙을 그대로 사용하며 새 안정화 시간을

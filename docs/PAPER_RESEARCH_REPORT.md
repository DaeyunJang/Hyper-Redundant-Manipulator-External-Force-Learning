## 1. 연구의 핵심과 현재 도달한 결과

사용자가 정의한 연구 대상은 여러 segment로 구성된 Hyper-Redundant Manipulator(HRM)의 **접촉점에 작용하는 3축 외력**과 **단일 접촉의 위치**다. 끝단 ID18의 힘을 어드미턴스 제어에 활용하는 것이 우선이며, body ID1–17의 접촉 위치도 구분하려 한다. 다만 이번 저장 모델의 실제 힘 학습·주 평가는 ID18에 한정되어 있어, 연구 목표와 완료된 검증 범위는 구분한다.

현재 실제 구현은 두 독립 네트워크의 조합이다.

- **힘 네트워크:** ID18 데이터에서 연속적인 Fx, Fy, Fz를 회귀한다.
- **위치 네트워크:** ID1–18의 접촉 위치를 분류한다. 무부하를 별도 ID0으로 학습하는 Class0와, 무부하를 위치 손실에서 제외하는 Masked를 비교한다.

두 네트워크는 가중치·입력 정규화·optimizer를 공유하지 않는다. 하나의 저장 파일로 묶지만, 공통 backbone을 학습하는 다중 과제 네트워크는 아니다.

## 2. 연구 문제의 정의

### 2.1 로봇과 접촉 ID

접촉 위치는 base 쪽 ID1부터 끝단 ID18까지의 segment index로 표현한다. ID18은 tip, ID1–17은 body로 구분한다. 이번 분석은 **한 시점에 하나의 접촉이 작용한다는 전제**를 사용한다.

데이터 수집 시 특정 segment에 케이블을 연결하고 힘을 가했다가 해제하는 과정을 기록했다. 이때 원본 contact_segment_id는 케이블을 연결한 위치이므로, 힘이 제거된 휴식 구간에도 같은 ID가 기록된다. 따라서 원본 ID만으로 실제 접촉 유무를 알 수 없으며, 실측 F/T 값으로 유부하·무부하 정답을 추가로 만든다.

2026-10-14 사용자 확인: CSV의 Fx/Fy/Fz는 **해당 contact ID 위치에 가한 외력의 성분**이다. 예를 들어 ID5 기록의 힘은 body ID5에서의 외력이며, ID18 기록의 힘은 tip에서의 외력이다. 힘의 작용 위치는 contact ID로, XYZ 성분의 표현 좌표계는 설정상 hrm_base로 구분한다. 이 정답의 물리적 의미와 아래의 실제 모델 학습 범위는 별개다.

사용자는 detection mode를 끄는 경우 끝단 힘 제어로 해석하고, contact ID18일 때만 힘을 갱신하도록 할 수 있다고 설명했다. 이는 제어측 사용 정책이며 학습 정답의 작용점을 바꾸거나 기존 가중치의 학습 범위를 확대하는 처리가 아니다.

현재 분류는 segment 단위의 이산 위치 추정이다. segment 내부의 연속적인 접촉 좌표, 접촉면 크기, 여러 접촉점의 분리, 분포하중 복원은 평가하지 않았다.

### 2.2 끝단 힘과 body 위치의 역할

이번 여섯 실험은 모두 force_scope=tip이다. 힘 네트워크는 **ID18 녹화의 실측 힘만** 학습하며, 유부하와 무부하를 모두 포함한다. 위치 네트워크는 ID1–18을 학습한다.

Body에 가해진 힘을 tip 힘 0으로 바꾸어 학습하지 않았다. 반대로 tip 전용 힘 네트워크가 body 접촉 중 출력한 값을 body 외력의 정답 추정으로 검증한 것도 아니다.

따라서 논문의 현재 결과는 다음처럼 기술하는 것이 정확하다.

> 끝단 접촉에 대한 3축 외력 회귀와, 단일 접촉의 segment 위치 분류를 독립적으로 학습·평가하였다.

“어느 위치에서 접촉하더라도 동일 힘 네트워크가 외력을 정확히 복원한다”는 주장은 현재 주 실험으로 뒷받침되지 않는다. 전체 ID 힘 회귀 설정은 별도 연구로 구분해야 한다.

과거 실험과의 구분: 2026-10-14 보존 기록을 추가 확인하여, 9/26의 구형 body 모델11종은 ID1–18의 힘도 학습했음을 확인했다. 이는 현재 독립 두 분기 실험 이전의 공유 encoder 모델이며 상세 이력은21절에 기록했다. 현재 여섯 실행의 학습 범위가 바뀌는 것은 아니다. 연구자는 향후 모든 접촉점의 힘을 모니터링하고 ID18의 힘만 어드미턴스 입력으로 사용하는 의도를 명확히 했다.

### 2.3 학습·평가·운용 정책의 구분

| 구분 | 현재 수행한 내용 |
| --- | --- |
| 학습 정답 | F/T 실측값으로 무부하 라벨을 만들고, 힘/위치 모델을 학습 |
| 오프라인 평가 | 저장된 예측과 GT를 비교하여 축별 힘 오차, ID 일치율, 허용거리 성공률, 접촉 유무 지표 계산 |
| 향후 실시간 운용 | 예측 힘 또는 별도 신호로 부하 문턱을 설정하고, tip 제어·body 접촉 표시·히트맵 등에 연결하는 구상 |

실시간에서 GT F/T를 사용할 수 있다는 전제로 평가한 것이 아니다. 평가할 때 GT를 사용해 “실제 접촉이 있었던 시점”을 구분한 것이며, 모델 입력에는 F/T 정답을 넣지 않았다.

2026-10-14 사용자 설명에 따르면 제어측은 현재 Class0 방식으로 구현되어 있으며, 향후 Class0/Masked를 선택 가능하게 할 계획이다. 이는 사용자 보고이며 이 저장소에서 외부 제어 코드를 실행·검증한 사실과 구분한다. 운용 규칙은 세 축이 모두 지정 범위 안이면 무부하, 한 축이라도 밖이면 유부하로 두고 유부하에서 위치 추정을 활용하려는 것이다. 운용 판정용 힘이 실측인지 추정인지와 실제 gate/ID0 처리 순서는 추가로 명시해야 한다. 추정 힘을 사용한다면 힘 추론 후 문턱을 적용하며, GT로 선택한 유부하 평가 성능을 실제 gate 성능으로 대체하지 않는다.

## 3. 전체 처리 흐름

실제 처리 흐름은 다음과 같다.

    CSV의 선택 입력 + 연속 XYZ 정답 + 원본 접촉 ID
      → 선택 열의 숫자가 없는 행 제거, 나머지를 원래 순서로 연결
      → 각 개발 CSV의 앞 80% train / 뒤 20% validation
      → train 원행만으로 분기별 입력 scaler와 힘 정답 scaler 추정
      → 표준화된 행에서 파일·역할 경계를 넘지 않는 30행 창 구성
      → 독립 힘 회귀 / 독립 위치 분류 학습
      → validation 기준으로 각 분기의 best epoch와 비교 모델 결정
      → 고정 test 파일에 예측
      → 집계 지표 + 행별 GT/예측 Excel 저장
      → organize로 모델별 열을 한 시트에 재배치

세 단계의 “선택”은 구분해야 한다.

1. 학습 중 best epoch 선택: 힘은 validation XYZ RMSE, 위치는 validation CE.
2. 여러 모델 조합 중 비교용 모델 선택: 힘 우선 선택과 위치 우선 선택이 서로 다름.
3. 이미 저장된 test 예측의 ±2/±3 채점: 예측이나 모델을 바꾸지 않는 평가 기준 변경.

### 4.1 여섯 입력 설정

| 문서 약칭 | 설정 및 결과 폴더 접미사 | 구성 | 차원 |

| C+A | cable_angle | 케이블 길이 4 + 상대각 18 | 22 |

| C+L+Estimated | cable_loadcell_estimated_pose | 케이블 4 + 장력 4 + Estimated XYZ 3 + quaternion 4 | 15 |

실제 입력 열과 단위는 다음과 같다.

| 입력 | CSV 열 | 단위·순서 |
| --- | --- | --- |
| 케이블 | wire.Cable #1 length ~ wire.Cable #4 length | 원자료 기록상 mm |
| 로드셀 | loadcell.Loadcell #1 tension ~ loadcell.Loadcell #4 tension | 원자료 기록상 g; 이 코드에서 N으로 환산하지 않음 |

| Estimated 위치 | estimated_tip.x_m / y_m / z_m | m, XYZ |
| Estimated 회전 | estimated_tip_orientation.qx / qy / qz / qw | 무차원 quaternion |
| FK TF 위치 | fk_tip_tf.x_m / y_m / z_m | m, XYZ |
| FK TF 회전 | fk_tip_tf.qx / qy / qz / qw | 무차원 quaternion |

입력 순서는 해당 실행의 resolved_config.json에 저장된 순서를 따른다. Quaternion에 대한 별도 부호 정렬, 회전 표현 변환, 보간, 단위 quaternion 재정규화는 수행하지 않았다.

2026-10-14 사용자가 설명한 의도는 다음과 같다. Estimated는 영상으로 추정한 곡선의 점과 국소 방향에서 얻는 끝단 자세이며, FK는 추정 상대각을 pan–tilt 교대 구조의 이론적 기구학 chain에 대입한 끝단 자세다. 따라서 비교의 의미는 **곡선에서 직접 구한 자세와 기구학 chain으로 재구성한 자세의 비교**다. 사용자 설명에는 접선과 법선이 함께 등장하므로, 최종 quaternion을 구성하는 축과 roll 기준은 구체화가 필요하다.

별도로 확인한 당시 세션 메타데이터에는 아래와 같이 기록되어 있다. 특히 Estimated quaternion의 filtered DH orientation 설명은 사용자가 설명한 기구학 비의존 자세와 차이가 있어, 실제 CSV 생성 버전에서 어떤 회전을 저장했는지는 미확인 사항으로 남긴다. Estimated와 FK TF를 각각 “독립 실측 자세”와 “무부하 기준 자세”라고 임의로 바꾸어 서술하지 않는다.

| 저장값 | 세션 메타데이터에 기록된 생성 의미 |
| --- | --- |
| Estimated XYZ | /estimated_tip_position: 설정된 하드웨어 길이 보정을 적용한 fitted curve의 마지막 경계점, hrm_base의 XYZ(m) |
| Estimated quaternion | /tf의 estimated_segment_center_19: 마지막 링크의 filtered DH orientation. Depth에서 독립 측정한 roll이 아님 |
| FK XYZ 별도 열 fk_tip | /kinematics/fk_tip_position: angle-derived FK tip |
| 이번 FK 입력 fk_tip_tf | /tf의 hrm_fk_tip: FK 위치와 orientation을 같은 TF에서 사용 |

메타데이터 기준으로 Estimated 위치는 곡선 끝점이며 링크 중심의 위치를 대신 쓰는 것은 아니다. Quaternion은 xyzw 원값을 사용한다. 두 입력을 완전히 독립된 센서의 자세 비교라고 해석하지 않는다. 실제 곡선 피팅, 각도 계산, FK의 입력 토픽·DH 파라미터·변환 곱 순서를 구현한 상위 producer 코드는 이 저장소에서 확인하지 못했으므로, 사용자 설명·당시 메타데이터·현재 CSV의 실제 생성 구현을 구분한다.

근거: 대표 힘 세션의 [recording_config.json](../datasets/20260926_f_ext_datasets/sine-35deg-both_seg-id-11_right/recording_config.json), [summary.schema.json](../datasets/20260926_f_ext_datasets/sine-35deg-both_seg-id-11_right/csv/summary.schema.json).

현재 여섯 실행에는 comparison_columns가 없다. 각 설정에서 실제 사용하는 입력·정답 열을 기준으로 유효행을 선택했으며, 처음부터 모든 입력 조합의 공통행만 학습한 실험은 아니다.

### 4.4 수집 방법에 관해 확정할 수 있는 범위

한 CSV는 한 접촉 ID의 기록이며, 외력 인가와 제거 구간이 함께 포함된다. Dynamic과 static이라는 파일 범주가 존재한다. 다만 파일명만으로 정확한 운동 주파수, 자세별 유지 시간, 외력 크기·방향·반복 횟수 등을 확정하지 않는다.

사용자는 자세 결측을 ROS bag의 가장 최근 TF 데이터로 보완했다고 설명했다. 최신 train에서는 세 입력 구성의 숫자행 수가 같아졌지만 test의 자세 결측은 여전히 평가 행을 줄인다. 최근값 보완의 시간 오차, 지연, 인과성은 이 문서 작성에서 상위 수집 코드까지 검증한 사항이 아니다.

### 4.5 장치·3D 생성·실험 조건의 추가 확인 범위

사용자 확인: D405는 실험에서 HRM의 비스듬한 상단 약45°에 배치했다. 영상 처리의 순서는 image → binary → skeleton → extrapolation → curve fitting → segment 수에 따른 구간 분할 → 해당 지점의 접선벡터 → segment 각도다. 카메라와 HRM base 사이의 좌표변환을 사용해 형상·각도를 hrm_base에서 표현한다. 이 설치각45° 자체가 완전한 외부 파라미터 교정을 대신한다는 뜻은 아니다.

대표 힘 세션의 [session.json](../datasets/20260926_f_ext_datasets/sine-35deg-both_seg-id-11_right/session.json) runtime parameter도 D405, RGB, RGB에 정렬된 depth, CameraInfo 입력을 확인해 준다. 위 영상 처리 흐름은 사용자 설명으로 확인됐으나, depth 역투영을 적용하는 정확한 단계·곡선 차수·피팅 수식·3D 각도 계산식은 producer 구현을 확인하지 못했다. 특히 quartic fitting이라고 확정하지 않는다.

하드웨어 snapshot은 고정 proximal segment를 포함한 19개 기하 segment와 18개 교대 1축 관절(tilt 9/pan 9)을 기록한다. 상대각18은 관절 인덱스에 따라 홀수 tilt·짝수 pan을 선택한다. 다만 실험의 contact ID1–18이 관절축·링크중심·표면 부착점 중 어디에 대응하는지는 별도 실험 정의가 필요하다. ID18=tip이라는 연구 정의와 TF 이름 center_19의 숫자를 단순 동일시하지 않는다.

사용자는 이번 수집이3차원 실험이라고 확인했다. 같은 대표 힘 세션의 실제 robot_control runtime은 pan=[0,35,90], tilt=[0,35,0], sine 주기20초와 최대속도15deg/s를 기록하며, sine_status CSV에는 RUNNING: IK sine가 있다. 이 기록은 두 축 운동 설정과 실행 진단의 근거다. 개별 시점의 공간 형상과 힘 방향 분포를 새로 정량 분석한 것은 아니며 배열 각 원소의 의미를 수집 코드 없이 추가 추정하지 않는다.

Frozen force_alignment snapshot은 센서축 XYZ에서 hrm_base로 다음 변환을 기록한다.

    right: F_base = (Fy_sensor, −Fx_sensor, Fz_sensor)
    left:  F_base = (−Fy_sensor, −Fx_sensor, −Fz_sensor)

이는 저장된 고정 회전 규약이며 작용/반작용 부호 전환, 토크의 원점 이동, 단위 환산을 포함하지 않는다. 사용자 확인에 따르면 left/right는 HRM의 왼쪽/오른쪽에서 힘을 가한 기록을 구분하는 이름이며, 서로 다른 학습 정답 정의나 추가 입력이 아니다. 설정 기본값보다 각 session의 frozen snapshot이 해당 CSV 변환의 근거다.

사용자 확인: 각 ID에 탄성 케이블을 연결하고 반대쪽을 이전2D 연구에서 사용한 동일 F/T센서에 연결해 외력을 측정했다. 센서 자세를 유지하고 위치를 옮기며 수집했으며, 센서축과 hrm_base축의 방향을 교정해 힘 벡터를 변환했다. 힘 성분은 F_base=R_base_sensor F_sensor로 표현한다. 정확한 센서 사양, 힘 크기·방향·반복 횟수의 전체 프로토콜은 별도 기록이 필요하다. 실제 학습 열은 fts_kalman.aligned_fx/fy/fz다.

## 5. 결측 처리, 분할, 시간창

### 5.1 숫자행만 사용하는 전처리

현재 전처리는 numeric_compact다.

1. 설정한 입력 열과 XYZ 정답을 수치로 변환한다.
2. 빈칸·비수치·NaN·Inf가 있는 행을 제외한다. 학습에는 유효한 정수 ID도 필요하다.
3. 남은 행을 원래 순서대로 연결한다.
4. 원본 파일과 source_row를 남겨 결과의 출처를 추적한다.

선택하지 않은 센서 열의 결측만으로 행을 제거하지 않는다. 결측을 0이나 무부하로 채우지 않는다. 정답 없는 운용 추론에서는 입력만으로 추론할 수 있지만, 정답이 있는 평가에서는 X/Y가 유효한 행을 사용한다.

확인된 원본 오류는 정확한 SHA256에 연결한 라벨 예외로 처리한다. 앞 세 입력 실행의 summary_18-2.csv는 사용자 확인에 따라 원래 기록 ID1을 분석용 ID18로 해석한 이력이 있고, data_audit에 원본 ID와 effective ID가 함께 남아 있다. 뒤 세 입력 실행에서는 그 라벨 예외가 적용된 파일이 없었다. 여섯 실행 모두 저장 audit의 파일 제외 목록과 명시적 행 제외 규칙은 비어 있다. 원본 CSV를 이 처리 과정에서 덮어쓰지 않았다.

Valid, frame, matching-time 플래그와 timestamp 간격으로 별도 행 검사를 하지 않는다. Timestamp는 네트워크 입력이 아니며 추적용이다. 따라서 결측 제거 후 이웃하는 두 행 사이의 실제 시간 간격은 일정하지 않을 수 있다.

### 5.2 Train/validation/test

각 개발 CSV의 유효행 수를 N이라고 하면 cut=int(0.8×N)으로 앞부분을 train, 뒷부분을 validation으로 나눈다. 이후 역할별로 시간창을 만든다. 무작위 행 단위 8:2 분할이 아니다.

Test 폴더는 사용자가 별도로 준비한 파일을 읽는다. Body test는 같은 원 녹화의 뒤쪽을 분리한 구간이며, 새로운 독립 body 실험과 구분한다.

이 방식은 각 ID가 학습과 평가에 존재하도록 하면서 시간상 앞부분과 뒷부분을 나눌 수 있다. 그러나 같은 녹화의 자세·환경·센서 특성 및 시간 상관이 남으므로 독립 세션 일반화 검증보다 제한적이다.

### 5.3 30행 창

현재 창은 마지막 행을 포함한 30행, stride 1이다. 시점 t를 예측할 때 t−29부터 t까지의 보존행을 제공한다. 파일 경계와 train/validation 경계를 넘는 창은 만들지 않는다.

각 파일·역할의 앞 29행은 이력을 준비하는 데 쓰이므로 예측 끝행으로 평가하지 않는다. MLP도 다른 모델과 같은 끝행을 평가하지만, 네트워크 내부에서는 마지막 한 행만 사용한다.

30은 현재 선택한 길이이며 최적 길이 실험의 결론이 아니다. 결측 연결을 허용하므로 30행을 항상 일정한 몇 초 또는 몇 ms로 환산해서는 안 된다. RNN은 창마다 hidden state를 새로 시작하며 이전 창의 상태를 이어받지 않는다.

## 6. 무부하 라벨과 두 학습 방식

### 6.1 실제 사용한 경계

| 축 | 무부하 하한 | 무부하 상한 |
| --- | ---: | ---: |
| Fx | −134.326 mN | +134.326 mN |
| Fy | −126.814 mN | +126.814 mN |
| Fz | −192.670 mN | +192.670 mN |

세 축이 **모두** 범위 안이면 무부하이며 경계를 포함한다. 한 축이라도 벗어나면 유부하다. 이는 합력 하나에 대한 문턱이 아니라 3축별 범위 판정이다.

예를 들어 Fx=150, Fy=0, Fz=0 mN이면 합력이 200 mN 미만이어도 유부하다. 반대로 각 축이 모두 범위 안이면 합력이 한 축의 문턱보다 커도 무부하일 수 있다.

현재 주 실험에서는 CSV 값에 범위를 직접 적용한다. 평균 offset 차감, 자동 10% 확대, 유부하/무부하 사이의 불확실 구간은 없다. 이전 자동 교정 실험과 혼용하지 않는다.

2026-10-14 경계의 숫자 유래를 원본으로 재검산했다. aidin_FT_sensor_validation_2의 Kalman aligned 2,797행 중 앞 70%인 1,957행에서 축별 평균 μ와 표본표준편차 s(ddof=1)를 구하고, 각 행의 score=max(|Fx−μx|/sx, |Fy−μy|/sy, |Fz−μz|/sz)를 계산했다. 그 score의 경험적 95% 분위수 q=2.4772739551791942에 1.1을 곱한 반폭 h=1.1×q×s가 각각 134.3262539944 / 126.8141590871 / 192.6699857859 mN다.

따라서 현재 고정 숫자는 관측 min/max나 최대 절댓값을 그대로 대칭화한 것이 아니다. 표준편차로 정규화한 **3축 최대 잔차의 공동 경험적 분위수**에서 유래한다. 정확히 ±3σ 또는 각 축의 95% 구간이라고 부르지 않는다.

과거 자동 기준은 평균 μ=[−67.362099,19.592977,−85.572715]mN를 뺀 판정용 힘에 이 반폭을 적용하고 더 큰 유부하 경계와 uncertain도 사용했다. 현재 수동 기준은 이 반폭을 반올림하여 CSV 값의 0 중심 대칭 범위로 사용한다. 10%를 실행 때 다시 곱하지 않지만 고정 숫자의 유래에는 당시 10% 확대가 들어 있다. 두 판정은 동일하지 않으며, 현재 수동 기준의 모든 세션 포함률이 95%라고 보장하지 않는다.

교정과 학습은 같은 종류의 fts_kalman.aligned_fx/fy/fz, hrm_base 채널을 사용한다. 무부하 기록의 실제 변환 (−Fy_sensor,−Fx_sensor,−Fz_sensor)도 전 2,797행에서 대조했다. Kalman 내부 Q/R·초기 상태·tare가 모든 세션에서 같았다는 뜻은 아니다. 근거는 [보존 calibration.json](../results_1006/train/20261006_095933/calibration.json)과 [무부하 세션 메타데이터](../datasets/aidin_FT_sensor_validation_2/csv/session_metadata.csv)다.

2026-10-14 사용자 설명은 **약5분 무부하 raw 신호를 필터 없이 측정하고, 비정상 노이즈를 아웃라이어로 제외한 뒤 표준편차 기준으로 범위를 정했다**는 것이다. 이는 사용자가 수행한 센서 측정 절차로 기록한다. 다만 위에 보존된 현재 숫자의 계산 이력은 Kalman-aligned 열과 경험적 분위수/1.1배를 사용하므로, 현재 결과의 라벨 기준을 raw 표준편차 방식으로 산출했다고 소급 서술하지 않는다. Raw 측정의 정확한 표준편차 배수·이상치 제외 규칙 및 현재 수동값과의 연결은 확인이 필요하다. 이번 설명 수정으로 경계나 기존 라벨은 바꾸지 않았다.

### 6.2 Masked

출력은 ID1–18의 18개 logits다. GT 유부하인 창의 끝행에 실제 ID를 부여하여 cross-entropy를 계산한다. GT 무부하 끝행은 위치 손실 계산에서 제외한다.

이는 무부하 데이터가 파이프라인에서 모두 사라진다는 뜻이 아니다. 과거 입력창에는 무부하 행이 들어갈 수 있고, 위치 입력 scaler도 전체 위치 train 행으로 계산한다. 힘 회귀는 계속 유부하·무부하의 실측 힘을 학습한다.

Masked에는 무부하 클래스가 없다. 실제 무부하에서도 ID1–18 중 하나를 출력하므로, 그 출력만으로 접촉이 있다고 판단할 수 없다.

### 6.3 Class0

출력은 ID0–18의 19개 logits다. GT 유부하는 실제 ID, GT 무부하는 ID0으로 cross-entropy를 계산한다.

최종 argmax가 0이면 모델의 무부하 판단이고, 1–18이면 모델의 유부하·접촉 위치 판단이다. 별도 검출 네트워크를 추가한 구조는 아니다.

### 6.4 두 방식에서 같은 것과 다른 것

| 항목 | Masked | Class0 |
| --- | --- | --- |
| 힘 정답 | ID18의 연속 실측 XYZ | 동일 |
| 힘 손실 | MSE | 동일 |
| 위치 출력 | ID1–18 | ID0–18 |
| 유부하 위치 손실 | 실제 ID의 CE | 동일 |
| 무부하 위치 손실 | 제외 | ID0의 CE |
| 자체 무부하 검출 | 없음 | 있음 |
| 과거 무부하 입력이 창에 포함될 수 있는가? | 가능 | 가능 |

독립 힘 모델이므로 무부하 학습 방식의 차이가 힘 회귀 정답을 바꾸지 않는다. 다만 각 조합을 독립적으로 다시 학습하므로 모든 힘 가중치와 결과가 동일하다는 뜻은 아니다.

## 7. 입력·정답 정규화와 손실

### 7.1 입력 표준화

각 feature j에 대해 train 행에서 평균 μj와 표준편차 σj를 구하고 다음을 적용한다.

    x̃j = (xj − μj) / max(σj, 10⁻⁸)

표준편차는 ddof=0이다. 겹치는 30행 창을 펼쳐 같은 행을 반복 가중하지 않고 원 train 행으로 계산한다.

Scaler 통계에는 해당 분기의 유효 train 원행을 모두 사용하며, 창의 끝행으로 채점되지 않는 각 train 구간의 초기 29행도 포함한다.

- 힘 입력 scaler: ID18 train 행에서 계산.
- 위치 입력 scaler: 전체 ID의 train 행에서 계산.
- Validation/test는 scaler 추정에 사용하지 않음.
- Masked 위치 scaler도 유부하 행만으로 제한하지 않음.

같은 입력 열을 사용해도 힘·위치 scaler가 다를 수 있다. 향후 제어 코드에서는 두 scaler를 각각 복원해야 한다.

### 7.2 힘 정답 표준화와 손실

힘은 먼저 mN에서 N으로 바꾼 뒤 train ID18 정답의 축별 평균·표준편차로 표준화한다. 표준편차 하한은 10⁻⁶ N이다.

    LF = Σi Σa (F̃pred,i,a − F̃gt,i,a)² / (3B)

여기서 a는 x/y/z, B는 배치 크기다. 축별 표준화를 사용하므로 이 손실은 물리 단위의 각 축 오차를 동일한 가중치로 합산한 MSE와는 다르다. 예측은 역표준화하여 N으로 되돌리고, 보고에는 mN을 사용한다.

### 7.3 위치 손실

위치 모델은 가중치 없는 cross-entropy를 사용한다. Masked는 GT 유부하 끝행만, Class0는 유부하·무부하 끝행 모두를 supervision으로 사용한다.

거리 기반 추가 손실, ordinal regression, label smoothing, 클래스 가중치, 균형 sampler는 이번 주 실험에 적용하지 않았다. 정답에서 멀리 떨어진 ID를 더 강하게 벌하는 학습을 수행한 것은 아니다. ±2/±3은 평가 단계에만 사용했다.

## 8. 비교한 11개 네트워크

모든 모델은 encoder의 마지막 시점 표현에 선형 출력 head를 연결한다. 힘 head는 표준화된 힘 좌표의 3개 실수, Masked 위치 head는 18개, Class0 위치 head는 19개 logits를 출력한다. 힘 출력에 tanh나 clipping 제한은 없다.

### 9.3 비교 표에서 어떤 모델을 선택했는가?

**힘 표:** 기존 predict summary의 validation 힘 우선 선택을 사용한다. 최저 validation 힘 RMSE에서 0.001 mN 이내의 조합을 모은 뒤 위치 macro recall, 위치 CE, 모델명 순으로 동률을 정리한다. 0.001 mN는 수치 동률 처리이며 통계적 동등성을 뜻하지 않는다.

**ID 표:** 모든 완료 조합 중 저장된 validation 정확 ID macro recall이 가장 높은 조합을 선택한다. 동률은 CE, 힘 RMSE, 모델명 순으로 처리한다. Test 정확도가 가장 높은 조합을 다시 고른 것이 아니다.

다만 기존 위치 validation macro recall은 Class0에서도 ID0을 제외한 위치 후보의 지표다. 이번 문서의 test 주표는 사용자의 최신 요청에 따라 **최종 ID0–18 출력**으로 보고한다. 선택 지표와 보고 지표가 완전히 같지는 않으며, 이를 숨기거나 최종출력 기준으로 재선택한 것처럼 쓰지 않는다.

기존 validation 위치 점수는 ID18도 포함하지만, 주 body test 표는 ID1–17만 평가한다. Validation 점수와 본문의 body test 정확도는 평가 대상도 다르므로 단순한 train/test 일반화 차이로 바로 해석하지 않는다.

힘 표와 ID 표의 선택이 다른 실제 예는 다음과 같다.

| C+L+A Class0 | 선택 bundle의 힘 / 위치 | Tip2 XYZ RMSE | Body 최종 ±2 / ±3 |
| --- | --- | ---: | ---: |
| 기존 힘 우선 summary | ResNet / ResNet | 90.23 mN | 60.56% / 65.45% |
| 위치 우선 분석 | MLP / Transformer | 92.53 mN | 72.53% / 74.50% |

이 차이는 표가 틀려서가 아니라 선택 목표와 bundle이 다르기 때문이다. 힘 90.23 mN와 위치 72.53%를 같은 bundle의 성능으로 쓰면 안 된다.

## 10. 평가 지표와 분모

### 10.1 축별 힘 오차

오차 eᵢ,ₐ = Fpred,ᵢ,ₐ − Fgt,ᵢ,ₐ를 mN으로 계산한다.

    RMSEa = sqrt(Σi eᵢ,ₐ² / N)
    MAEa  = Σi |eᵢ,ₐ| / N

Fx/Fy/Fz 각각 계산한다. RMSE는 큰 오차에 더 민감하고 MAE는 절댓값 오차의 평균이다.

### 10.2 XYZ 통합 오차

    RMSEXYZ = sqrt(Σi Σa eᵢ,ₐ² / (3N))
    MAEXYZ  = Σi Σa |eᵢ,ₐ| / (3N)

XYZ RMSE는 축별 RMSE 세 개의 산술평균이 아니라 제곱평균의 제곱근이다. 합력 크기 차이의 RMSE와도 다르다.

벡터 오차 norm에 대한 sqrt(mean(||e||²))를 계산하면 위 XYZ RMSE의 √3배다. 논문·MATLAB·기존 결과에서 정의를 통일해야 한다. 힘 크기가 0 근처인 행이 많아 퍼센트 오차를 주지표로 사용하지 않았다.

### 10.3 실제 유부하에서의 접촉 위치 정확도

주 평가집합 S는 **실측 힘 기준 GT 유부하이고, 정답 ID가 body 1–17인 행**이다.

    An = 100 × Σi∈S [예측ID≥1 이고 |예측ID−GT ID|≤n] / |S|

n=0은 정확 ID, n=2는 ±2, n=3은 ±3 성공률이다. Masked는 원래 ID1–18만 출력한다. Class0가 ID0을 출력하면 n과 무관하게 실패다. 예를 들어 정답 ID1에 예측 ID0이 숫자상 가깝더라도 ±2 성공으로 세지 않는다.

GT가 ID10이라면 ±2 성공 범위는 ID8–12다. 이것은 세 구간을 직접 학습하거나 확률을 합산한 값이 아니다. 미리 정해진 고정 상·중·하 구간과도 다르다.

예측이 유부하라고 판단된 행만 골라 분모를 줄이지 않는다. Class0의 접촉 누락도 같은 GT 유부하 분모에 남아 실패로 반영된다.

### 10.4 Micro, macro, ID별 지표

주표는 모든 평가행을 합한 micro 성공률이다. 긴 기록이나 유부하 행이 많은 ID의 비중이 커진다.

Macro 성공률은 각 ID의 recall을 먼저 구한 뒤 지원 표본이 있는 ID끼리 동일한 가중치로 평균한다. ID별 support를 함께 남긴다. 지원 표본이 없는 ID를 0%로 대체하거나 높은 정확도로 간주하지 않는다.

Masked에서는 평균 segment 거리 E[|예측ID−GT ID|]도 의미가 있다. Class0의 ID0은 물리적 segment가 아니므로, 최종 ID0을 그대로 거리 1·2 등으로 계산하는 위치 MAE는 주지표로 쓰지 않는다.

### 10.5 Class0의 부하 판별

| GT / 예측 | 예측 ID1–18 | 예측 ID0 |
| --- | --- | --- |
| GT 유부하 | TP: 접촉 검출 | FN: 접촉 누락 |
| GT 무부하 | FP: 잘못된 접촉 검출 | TN: 무부하 정답 |

- 유부하 검출률 = TP / (TP+FN).
- 무부하 정답률 = TN / (TN+FP).
- 무부하 오검출률 = FP / (TN+FP).

이 지표는 위치가 맞았는지와 별개다. GT ID5를 ID15로 예측하면 접촉 검출은 성공이지만 위치는 틀렸다.

### 10.6 이전 conditional / incl. detection 용어와의 연결

독자의 혼동을 줄이기 위해 본문은 “최종 출력의 유부하 위치 정확도”와 “접촉 유무 판별”로 설명한다.

기존 파일의 Class0 conditional은 ID0의 확률 p0를 제외하고 ID1–18 중 argmax를 취한 후보를 평가한다. 모델의 최종 출력이 0인 경우에도 강제로 위치 후보를 뽑으므로, 실제 최종 ID 성능과 다르다. 기존 incl. detection은 최종 ID0을 실패로 계산하며 **이 문서의 Class0 주 위치 지표에 대응**한다.

두 기존 지표 모두 GT 유부하가 분모다. incl. detection이라는 이름이 GT 무부하 행까지 분모에 추가한다는 뜻은 아니다. 기존 후보 분석은 참고 진단으로 남기되 주 결과로 혼합하지 않는다.

구현상 Masked의 ID1–18 argmax는 conditional_id에 저장되고, 운용 상태를 포함하는 final_id 필드는 제공하지 않는다. 이 문서의 “Masked 최종 ID”는 그 모델이 선택한 **위치 argmax**를 뜻한다. 무부하를 판정하는 운용 ID가 추가되었다는 의미는 아니다.

### 10.7 정답률과 softmax 확률은 다르다

한 행에서 p1…p18은 각 segment에 대한 모델의 출력 점수이며, Class0에는 p0도 있다. 그중 최대 확률의 ID를 선택해 GT와 맞는지 채점한 비율이 정확 ID 정답률이다.

반면 “정답 ID의 평균 확률”은 각 행에서 GT ID에 부여한 확률 pGT를 평균한 값이다. 확률 0.4라도 다른 ID보다 높으면 그 행은 정확한 예측일 수 있다. 확률 0.9로 잘못된 ID를 고르면 그 행은 실패다. 따라서 평균 확률과 정답률은 같은 지표가 아니다.

GT 주변 ±n의 확률 합 Σpⱼ (|j−GT ID|≤n), 예측 ID 주변 ±n의 확률 합, 실제 argmax의 ±n 정답률도 서로 다르다. 이 문서의 88.67%·92.48%는 마지막 **정답률**이다. GT 주변 확률은 오프라인에서만 GT를 이용해 계산할 수 있고, 예측 주변 확률은 운용에서 계산 가능하지만 실제 접촉이 그 안에 있을 보정된 신뢰확률로 검증한 것은 아니다.

### 10.8 고정 구간 평가와 허용거리 평가

과거 구간 평가는 각 구간의 ID 확률을 합한 뒤 가장 큰 합을 갖는 구간을 예측한다.

    P(구간 G) = Σj∈G pj
    예측 구간 = argmaxG P(G)

확률을 합하므로 “최대확률 ID가 속한 구간”과 결과가 다를 수 있다. Class0 검출 포함 구간 평가에서는 최종 ID0이면 실패다. 구간 경계를 선택할 때는 validation을 사용하며 test를 보고 경계를 최적화한 성능을 독립 test 결과로 쓰지 않는다.

사용자가 논의한 2×2 비교는 다음과 같이 정리할 수 있다.

| 학습 방식 / 평가 관점 | 고정 body 구간 | 정확 ID와 ±n segment |
| --- | --- | --- |
| Masked | 기존 ID 확률을 구간별 합산하여 평가 | 기존 ID argmax의 거리로 평가 |
| Class0 | 같은 구간 평가, ID0 검출 누락 별도 반영 | 최종 ID0을 실패로 계산 |

이는 **두 가지 학습 방식에 두 가지 위치 평가 관점을 적용**한 것이다. 네 종류의 새로운 학습 알고리즘을 각각 개발했다는 뜻은 아니다. 이번 본문의 최신 수치는 ±n에 집중하며 과거 구간 수치를 같은 조건의 결과로 섞지 않는다.

## 13. Tip/body 구분과 위치 오차를 구분하기

±n은 가까운 위치를 찾았는지를 측정한다. 예를 들어 GT body ID17을 tip ID18로 예측하면 ±1 성공이지만, 제어에서 tip/body를 나눌 때는 잘못된 라우팅이다.

주 C+L+A 위치선택 모델의 GT 유부하 body 8,242행에서:

- Masked가 최종 ID18을 출력한 비율: **4.46%**.
- Class0가 최종 ID0을 출력한 비율: **22.42%**.
- Class0가 최종 ID18을 출력한 비율: **2.45%**.
- Class0가 최종 ID1–17을 출력한 비율: **75.13%**.

마지막 75.13%가 정확한 body 위치를 맞혔다는 뜻은 아니다. Body 범주로 출력했다는 의미다.

특히 GT ID17의 222행 중 Masked는 160행(**72.07%**), Class0는 134행(**60.36%**)을 ID18로 예측했다. 전체 body 평균의 tip 오인 비율만 보면 이 끝단 인접 위치의 약점이 가려질 수 있다. ID17의 높은 ±2 성공률을 tip/body 구분이 잘 되었다는 의미로 해석하지 않는다.

별도 tip2의 GT 유부하 930행에서는 같은 위치선택 Transformer의 정확 ID18 출력률이 Masked **98.17%**, Class0 **72.90%**였다. Class0의 나머지는 이 평가에서 무부하0으로 출력되었으며 body1–17 출력은 없었다.

같은 tip2 파일의 GT 무부하 행에서 Class0 오검출률은 **17.78%**로, body 파일의 5.15%와 다르다. 파일마다 다른 부하·자세 분포가 있으므로 하나의 검출률을 모든 실험에 일반화하지 않는다.

향후 제어에서 기준 힘 이하를 운용상 ID18로 취급하는 것은 기본 동작 정책이다. 그것을 모델이 tip 접촉을 정확히 검출한 것으로 채점해서는 안 된다. 원래 예측 ID, 부하 판단, 기본값 적용 여부는 구분할 필요가 있다.

## 15. 유사한 내부 센서값에서 다른 힘·형상이 나타나는 사례

입력 구성의 필요성을 살펴보기 위해 datasets/20260926_f_ext_datasets의 여러 summary를 대상으로 케이블 길이와 로드셀 장력이 가까운 시점을 탐색했다. 이것은 모델의 정확도 평가와 별개의 자료 탐색이다.

처음에는 떨어진 두 ID끼리 유사 입력 사례를 찾았고, 이후 사용자의 의도에 맞추어 여러 ID를 한 묶음으로 비교했다. ID1–18 전체가 동시에 케이블 0.05 mm/장력 5 g 허용차를 만족하는 묶음은 찾지 못했다.

케이블 0.05 mm/장력 5 g는 사례 검색을 위해 지정한 척도이며 센서 잡음·분해능이나 물리적으로 구별 불가능한 차이로 검증한 값은 아니다.

이후 ID 간 간격을 둔 다섯 ID의 근접 묶음에서는 **ID1·7·10·15·18** 사례가 지정한 거리 기준에서 가장 가까웠다. 그 묶음의 최대 케이블 차이는 **0.073328 mm**, 장력 차이는 **9.23 g**, 힘 벡터 차이는 **1,026.70 mN**였다. 원본 파일명과 행 번호를 당시 Excel에 기록했다.

이 탐색은 유부하 85,520행에서 이웃한 선택 ID 간격≥3, 최소 ID≤3, 최대 ID≥16을 만족하는 210개 ID 조합을 대상으로 했다. 다섯 행의 각 채널 최대−최소를 케이블 0.05 mm/장력 5 g로 나눈 뒤, 8개 정규화 범위 중 최댓값을 최소화했다. 결과의 최댓값은 J=1.846으로 앞의 엄격한 허용차를 모두 만족한 것은 아니다. 해당 조건에서 최소임을 확인한 것이며 다른 거리 척도에서도 최선이라는 뜻은 아니다. 상대각은 18개 중 최대 6.13° 차이가 있었다.

이 사례는 내부 길이·장력이 비슷해도 접촉 위치에 따라 외력 또는 형상과의 대응이 달라질 수 있다는 연구 동기를 제공한다. 다만 완전 동일 입력의 수학적 비식별성 증명도, 데이터 전체에서의 보편적 통계도 아니다. 단일 시점 근접 탐색이며 시계열 이력이 같은지까지 맞추지 않았다.

논문에 쓴다면 주 성능표와 분리한 보조 사례 그림으로 제시한다. 자세한 탐색 기준과 파일·행은 [통합 기록 100–105절](CHATGPT_README.md) 및 [다섯 ID 사례 Excel](../results/analysis/20261011_183433_five_id_similar_inputs/five_id_similar_inputs.xlsx)을 따른다.

사용자는 이 사례를 논문 도입에서 base부터tip까지 떨어진 접촉점에 서로 다른 외력이 작용해도 내부 길이·장력만으로 구분하기 어려울 수 있음을 보여주는 동기 그림으로 사용할 계획이다. 별도로 보유한 영상/형상을 직접 정리할 예정이며 아직 이 대화에 첨부하지 않았다. 아래 원자료 확인은 이 저장소에 있는 파일만을 대상으로 하며 사용자의 전체 보유 자료가 없다는 뜻이 아니다. “센서 반복 측정 변동”은 같은 물리 상태를 여러 번 측정할 때 값이 흔들리는 정도를 뜻한다. 현재 사례는 이 변동과 비교한 실험이 아니어도 근접 입력의 사례 그림으로 사용할 수 있다. 다만 최종5사례 모두가0.05mm/5g 이내였다고 쓰지 않고 실제 최대 차이를 함께 제시한다.

2026-10-14 원자료 확인: 다섯 사례의 원 세션에 rosbag과 cropped RGB PNG가 남아 있다. ID1/7/10/18은 선택 CSV 행의 기준 timestamp와 이미지 index가 정확히 일치하지만, ID15는 가장 가까운 RGB가 약33.34ms 앞이고 해당 행의 estimated_tip source time은 기준시각과 약1.767초 차이가 난다. 영상 내용이나 물리적 동기화까지 검증한 것은 아니다.

다섯 세션의 cropped-depth 저장 수는 모두0이다. 기존 각도·tip 좌표·TF 수치 기록은 있으나 원 depth에서 동일 3D 형상을 재생성할 수 있다고 보장하지 않는다. 별도의 9/27 AprilTag/shape 네 세션에는 RGB/depth 및 tag pose 기록이 있어 두 자료군을 구분해야 한다.

## 16. 결과가 말해주는 것

### 16.1 끝단 힘과 body 위치는 같은 입력 요약을 요구하지 않을 수 있다

현재 평가에서는 끝단 자세 입력을 사용한 선택 모델이 낮은 tip 힘 오차를 보였지만, body 위치는 상대각 18개를 사용하는 모델이 더 잘 구분했다.

가능한 해석은 끝단 자세가 전체 형상의 일부 정보를 요약하는 반면, 여러 상대각은 분포된 변형 정보를 보존할 수 있다는 것이다. 그러나 현재 비교만으로 그 기전을 증명한 것은 아니다. 학습 자료, 결측 표본, 모델 선택을 통제한 후속 실험이 필요하다.

### 16.2 정확 ID와 근접 위치는 다른 해상도의 결과다

Masked에서 정확 ID 66.40%에 비해 ±2 88.67%, ±3 92.48%가 높다는 것은 오분류의 상당 부분이 정답 근처에 있다는 뜻이다. 개별 segment를 항상 정확히 식별한다는 뜻은 아니다.

논문에서는 “정확도 개선”보다 **허용 위치 오차에 따른 성공률** 또는 **localization accuracy within ±n segments**로 표현하는 편이 정확하다.

### 16.3 접촉 검출과 위치 판별의 실패 원인을 나누어 볼 수 있다

Class0는 무부하 정답률이 높았지만 실제 body 접촉의 22.42%를 놓쳤다. 같은 GT 유부하에서 최종 위치 성공률이 낮아진 이유 중 하나가 이 누락이다.

따라서 무부하 판별까지 요구하는 모델과 유부하 위치만 학습하는 모델을 단일 숫자로 우열 평가하기보다, 각자의 역할과 지표를 분리하는 것이 합리적이다. Masked의 높은 위치 정확도만으로 상시 접촉 검출기를 완성했다고 주장할 수 없다.

### 16.4 독립 분기이므로 힘과 위치의 목표를 따로 최적화할 수 있다

현재 구현은 힘/위치의 아키텍처를 별도로 선택할 수 있는 장점이 있다. 그러나 저장된 힘 최선 bundle과 위치 최선 bundle의 분기를 새로 조립하여 운영하는 절차는 이번 문서 작성에서 구현·검증하지 않았다.

동일한 힘 아키텍처도 조합마다 새로 학습되어 파트너 간 tip2 RMSE 범위가 최대 20.55 mN까지 벌어졌다. 이 변동을 두 네트워크의 공동 학습이나 정보 교환 효과라고 설명하면 안 된다. 해당 원인과 반복 학습 안정성은 추가 연구 대상이다.

## 17. 논문에서 명시해야 할 한계

1. **독립 body 실험 검증이 아니다.** Body test는 동일 녹화의 분리 구간이다. 이미 결과 분석과 연구 방향 결정에도 사용되어 완전히 손대지 않은 최종 holdout이라고 부르지 않는다.
2. **힘의 주결과는 한 개 별도 tip 기록이다.** 다양한 세션·자세·접촉 방향에 대한 일반화를 충분히 입증한 것은 아니다.
3. **중복 tip 기록이 있다.** Train58의 ID18_right와 test summary_18_test는 같은 기록이므로 주 일반화 힘 표에서 분리했다. 실행이 허용된 것과 독립 평가인 것은 별개다.
4. **입력 비교 조건이 완전히 같지 않다.** 학습 파일 수·내용·test support·선택 모델이 일부 다르다.
5. **시계열 행은 독립 표본이 아니다.** 겹치는 창과 같은 녹화의 상관을 무시한 행 단위 신뢰구간·유의성 검정은 제시하지 않았다.
6. **여러 seed 반복이 없다.** 현재 seed 설정의 결과이며 평균±표준편차로 일반화하지 않는다.
7. **부하 GT도 선택한 경계에 의존한다.** Fx/Fy/Fz 경계를 바꾸면 유부하 분모·위치 학습 라벨이 달라진다. 현재 성능을 다른 문턱으로 자동 확장할 수 없다.
8. **Masked는 무부하 검출기가 아니다.** GT 유부하에서의 높은 위치 성공률과 실제 상시운용의 성공률은 다르다.
9. **±n은 물리 길이나 확률 신뢰구간이 아니다.** Segment 간 길이를 별도 정의하지 않고 mm 정확도로 환산하지 않는다.
10. **자세 결측 보완의 시간 정합은 별도 확인이 필요하다.** 최근 TF 사용이 센서 정합 오차를 완전히 제거했다고 볼 수 없다.
11. **Softmax 보정 검증이 없다.** 확률 0.8이 실제 80% 신뢰도라는 보장이 없다.
12. **실시간·폐루프 제어 실험은 여기서 검증하지 않았다.** 추론 지연, 제어 안정성, 안전성, 어드미턴스 추종 성능을 완료된 연구 결과로 추가하지 않는다.
13. **다중 접촉과 body 힘은 주 실험 범위가 아니다.** Tip 전용 회귀를 모든 접촉 위치의 힘 복원으로 확대 해석하지 않는다.

## 18. 논문에 사용할 수 있는 서술 초안

아래 문장은 현재 결과를 과장하지 않고 옮기기 위한 초안이다. 하드웨어와 수집 방법의 빈 정보는 22절을 보완한 후 추가한다.

### 18.1 연구 목적

> 본 연구에서는 다수의 segment로 구성된 HRM에 대해 끝단의 3축 외력과 단일 접촉의 위치를 추정하는 데이터 기반 방법을 비교하였다. 케이블 길이, 내부 장력, 상대 관절각 및 끝단 자세의 입력 구성을 비교하고, 힘 회귀와 접촉 위치 분류를 독립 네트워크로 구성하였다. 끝단 ID18의 힘은 연속값으로 회귀하였으며, 접촉 위치는 ID1–18의 이산 위치로 표현하였다.

### 18.2 데이터와 전처리

> 각 녹화 파일은 하나의 접촉 ID에 해당하며 외력 인가 및 해제 구간을 포함한다. 선택한 입력과 정답 열에서 유한한 수치가 없는 행을 제외한 뒤 원래 순서를 유지하였다. 각 개발 기록의 앞 80%를 학습, 뒤 20%를 검증에 사용하고 파일 및 분할 경계를 넘지 않는 30행 입력창을 구성하였다. 입력과 힘 정답의 정규화 계수는 학습 데이터만으로 추정하였다. Body 평가는 동일 녹화에서 별도로 분리한 구간을 사용했으며, 힘의 주 평가는 별도로 수집된 tip 기록을 사용하였다.

### 18.3 무부하와 위치 학습

> 실측 Fx, Fy, Fz가 각각 ±134.326, ±126.814, ±192.670 mN 범위에 모두 포함될 때 무부하로 정의하고, 하나 이상의 축이 경계를 벗어나면 유부하로 정의하였다. Masked 방식은 유부하 끝행에 대해서만 ID 분류 손실을 계산하였다. Class0 방식은 무부하를 ID0으로 추가하여 접촉 유무와 위치를 함께 분류하였다. 부하 라벨 산출에 사용한 실측 힘은 모델 입력에 포함하지 않았으며, 힘 회귀는 두 방식 모두 유무부하의 연속 정답을 사용하였다.

### 18.4 모델과 평가

> 11종의 힘 네트워크와 11종의 위치 네트워크를 두 가지 무부하 처리 방식으로 조합하여 입력 구성당 242개 조합을 학습하였다. 각 조합의 두 분기는 독립 파라미터와 optimizer로 초기화하였다. 힘 성능은 축별 및 XYZ 통합 RMSE·MAE로 평가하였다. 위치 성능은 실제 유부하 body 구간에서 정확 ID 일치율과 ±2, ±3 segment 이내의 성공률을 보고하였다. Class0가 해당 구간에서 ID0을 출력하면 위치 추정 실패로 처리하고, 접촉 유무 판별 성능은 별도로 보고하였다.

### 18.5 힘 결과

> 별도 tip 기록의 공통 2,572개 예측 시점에서, validation 기준으로 선택한 Class0 힘 모델의 XYZ RMSE는 케이블·장력·상대각 입력에서 90.23 mN, Estimated 자세 입력에서 82.60 mN, FK TF 자세 입력에서 81.93 mN였다. FK TF 입력 모델의 축별 RMSE는 Fx 98.08 mN, Fy 61.04 mN, Fz 82.41 mN였다. 상대각 입력 대비 통합 오차는 낮았으나 모든 축에서 일관된 개선을 보인 것은 아니다.

### 18.6 위치와 검출 결과

> 케이블 길이·장력·상대각을 입력으로 하는 Transformer를 실제 유부하 body 8,242개 시점에서 평가하였다. Masked 모델의 정확 ID 일치율은 66.40%였으며 ±2 및 ±3 segment 이내 성공률은 각각 88.67%, 92.48%였다. Class0 모델의 최종 출력에 대한 동일 지표는 53.91%, 72.53%, 74.50%였다. Class0는 실제 유부하의 77.58%를 검출하고 별도 무부하 구간의 94.85%를 올바르게 분류하였다. 이 결과는 정확한 개별 segment 식별과 허용 위치 오차 내의 추정, 그리고 접촉 검출을 구분하여 평가할 필요성을 보여준다.

### 18.7 Discussion과 범위

> 현재 결과는 상대각 정보를 포함한 입력이 body 접촉 위치를 구분하는 데 유용할 가능성과, 끝단 자세를 사용하는 입력이 tip 힘 회귀에 효과적일 가능성을 보여준다. 다만 입력별 학습 자료와 평가 가능한 행이 일부 다르고, body 평가가 동일 녹화에서 분리한 구간에 한정되므로 입력의 인과적 기여나 독립 세션 일반화를 단정할 수 없다. 향후 동일 표본과 여러 seed를 사용하는 통제 비교 및 독립 body 실험을 통해 이를 확인할 필요가 있다.

### 19.2 힘 그래프와 지표 계산

[analyze_matlab.m](../analyze_matlab.m)은 organized 힘 Excel의 force_all과 _rows를 읽는다. 기본 분석 파일은 summary_18_test_2.csv, 부하 조건은 all이다. GT와 각 모델의 pred_fx/fy/fz 열에서 유한한 행을 선택하고 축별·XYZ RMSE와 MAE를 계산한다.

GT에 이미 Kalman 처리가 반영되어 있으므로 저장 지표를 재현할 때 추가 필터를 적용하지 않는다. 이전 MATLAB 코드의 Fc=√(Fx²+Fy²)는 XY 평면 힘 크기이며 Fz가 아니다.

서로 다른 원본 녹화를 한 시간축으로 연속 연결한 그림은 피한다. Timestamp를 확보하지 못하면 “예측 표본 index”라고 표시하고, 근거 없이 30 Hz 또는 일정한 시간 간격을 가정하지 않는다.

### 19.3 ID 그림의 축과 캡션

혼동행렬의 세로축은 GT ID1–17, 가로축은 예측 ID1–18 또는 Class0의 ID0–18이다. 각 GT 행을 100%로 정규화하고 support를 함께 표시한다. 데이터가 없는 ID는 NaN/회색으로 표현한다.

허용거리 곡선의 예시 캡션:

> 동일 녹화에서 분리한 실제 유부하 body 8,242개 시점의 접촉 위치 성공률. 예측 ID와 GT ID 사이의 segment index 거리가 허용치 n 이하이면 성공으로 정의하였다. Class0의 ID0 예측은 모든 허용치에서 실패로 처리하였다.

힘 표의 예시 캡션:

> 별도 tip 기록 summary_18_test_2.csv의 공통 2,572개 예측 시점에서 평가한 힘 오차. XYZ RMSE는 세 축 성분의 제곱오차를 3N으로 평균한 뒤 제곱근을 취한 값이며, 단위는 mN이다. 모델은 validation에서 선택하였다.

MATLAB 자체 실행은 이 PC에서 검증하지 못했다. 기존 작업에서 MATLAB 문법 검사와 실제 Excel을 이용한 Python 동일 수식 대조는 통과했다. 이를 MATLAB 런타임 검증 완료로 표현하지 않는다.

### 20.3 Bundle이라고 부르는 이유

hrm_bundle.pt는 단순한 가중치 배열만이 아니라 다음 정보를 함께 보존하는 묶음이다.

- 힘/위치 네트워크 구조와 가중치.
- 입력 열 순서, 창 길이, 모드와 클래스 의미.
- 힘·위치 입력 scaler와 힘 정답 역정규화 정보.
- 힘 단위·좌표계·무부하 교정 기준 및 실행 설정.
- 데이터 분할·출처와 평가를 재현하기 위한 메타데이터.

제어에서 pt를 복사하는 것만으로 자동 추론이 되는 것은 아니며, 해당 버전의 모델 구조와 전처리를 복원하는 코드가 필요하다. 다만 bundle에 필요한 값이 모여 있으므로 현재 YAML을 다시 해석하여 추측할 필요를 줄일 수 있다.

### 20.4 집계표와 행별 예측의 차이

[force_and_id_all_combinations.xlsx](../results/analysis/20261012_092804_151908_comparison/force_and_id_all_combinations.xlsx)는 22시트의 **집계 분석 파일**이다. all_combinations에는 1,452개 조합의 지표가 있으며, 모든 시점의 GT/예측 배열을 담은 것은 아니다.

| 결과 | 저장 범위 |
| --- | --- |
| comparison / metrics | 모든 242조합의 집계 지표 |
| predictions.csv | 방식별 기존 validation 선택 조합의 행별 예측 |
| predictions.xlsx | 44개 대표분기 모델 시트 + 2개 요약 시트 |
| organized 힘 Excel | GT XYZ + 11개 힘 모델의 예측 XYZ를 같은 시트에 배치 |
| organized ID Excel | GT ID·부하 상태와 모델별 예측, 거리·허용범위 결과 |

44개 모델 시트는 2방식×(11힘+11위치)다. 힘 모델의 위치 파트너, 위치 모델의 힘 파트너를 설정의 첫 모델인 MLP에 고정한 대표분기다. 따라서 **모든 242조합의 모든 시점 예측이 Excel에 들어 있는 것은 아니다.**

Organized의 _rows로 원본 파일과 행을, _models로 대표 checkpoint를 확인할 수 있다. Source row는 원 CSV 데이터행의 0-based 인덱스이며 Excel 원본 줄 번호와 구분한다.

선택된 ResNet 힘을 분석하고 싶다면 모델명만 보지 말고 위치 파트너까지 확인한다. 예를 들어 MLP 파트너로 고정된 organized의 ResNet과 힘 우선 선택 ResNet/ResNet은 서로 다른 가중치일 수 있다.

## 부록 A. 직전에 합의한 쉬운 설명 — 원문 보존

아래는 사용자가 “방금 내용은 그대로 정리”해 달라고 요청한 설명을 보존한 것이다.

응. **논문에서는 “접촉 위치를 찾는 성능”과 “접촉 유무를 판단하는 성능”으로 나누면 훨씬 쉽게 설명할 수 있어.** 복잡했던 class0의 후보 분석은 본문에서 빼고, 모델이 실제로 출력한 ID를 기준으로 정리하자.

먼저 아래 결과는 **케이블 길이·로드셀 장력·상대각도를 입력으로 사용하는 Transformer**의 결과야. 위치 평가 대상은 끝단을 제외한 **body ID1–17의 실제 유부하 데이터 8,242행**이야.

**유부하 정답은 네가 지정한 Fx·Fy·Fz 범위로 만들었어.**

- Fx: ±134.326 mN
- Fy: ±126.814 mN
- Fz: ±192.670 mN

세 축 모두 범위 안이면 무부하, **한 축이라도 벗어나면 유부하**로 라벨링했어. 이 실측 힘은 정답을 만들기 위한 것이고, 모델 입력에 넣지는 않았어.

두 학습 방식은 이렇게 설명하면 돼.

| 방식 | 학습하는 내용 | 모델의 출력 |
|---|---|---|
| **Masked: 접촉 위치 추정** | 유부하 데이터에서 위치를 학습. 무부하 데이터는 ID 학습 손실에서 제외 | ID1–18 |
| **Class0: 무부하 판단 + 접촉 위치 추정** | 무부하는 ID0, 유부하는 해당 접촉 ID로 학습 | ID0–18 |

힘 회귀는 이 구분과 별개로, 유부하·무부하 모두에서 연속적인 힘 값을 학습해.

**같은 실제 유부하 데이터에서 위치를 얼마나 맞혔는지 비교하면 다음과 같아.**

| 학습 방식 | 정확한 ID 일치 | 정답에서 ±2 이내 | 정답에서 ±3 이내 |
|---|---:|---:|---:|
| **Masked** | **66.40%** | **88.67%** | **92.48%** |
| **Class0** | **53.91%** | **72.53%** | **74.50%** |

두 행의 평가 데이터는 동일해. Class0가 실제 접촉을 **ID0, 즉 무부하로 출력하면 실패**로 계산했어.

여기서 ±2는 정답이 ID10일 때 **예측 ID8–12를 성공으로 인정한다**는 뜻이야. 상·중·하 세 구간을 새로 분류한 것이 아니라, **위치 오차를 몇 segment까지 허용할지 바꾼 평가**야.

따라서 위치 추정 결과는 이렇게 표현하는 게 정확해.

> **Masked 모델은 정확한 segment ID를 66.40% 맞혔으며, ±2 segment를 허용하면 88.67%, ±3을 허용하면 92.48%의 정확도를 보였다.**

“정확 ID는 50~60%인데 구간으로 보면 90%”라고 묶으면 Class0와 Masked의 수치가 섞일 수 있어. **같은 방식의 수치를 연결해서 설명해야 해.**

Class0의 위치 성공률이 낮아진 이유를 이해하려면 **접촉 유무 판별을 따로 보면 돼.**

| 실제 상태 | 평가 행 수 | Class0가 상태를 올바르게 판단한 비율 |
|---|---:|---:|
| 실제 유부하 | 8,242 | **77.58%** |
| 실제 무부하 | 11,260 | **94.85%** |

즉, Class0는 무부하를 비교적 잘 알아봤지만, **실제 접촉의 22.42%를 무부하로 놓쳤어.** 이 누락이 위치 평가에서도 실패로 반영돼.

그래서 네 생각은 다음처럼 다듬으면 좋아.

- **“접촉이 있는 구간에서 위치만 찾는 모델은 높은 근접 위치 정확도를 보였다.”** → 맞는 설명이야.
- **“접촉 유무 판단까지 맡기면 실제 접촉을 놓치는 경우가 생겨, 접촉 위치를 최종적으로 맞히는 성공률이 낮아졌다.”** → 이번 결과에 맞는 설명이야.
- **“유부하만 전처리하면 모델 성능이 좋아진다.”** → 이번에는 학습 방식도 다르므로, 전처리만의 개선 효과라고 말하기는 어려워.
- **“무부하 데이터까지 평가에 넣으면 전체 정확도가 낮아진다.”** → 그렇지는 않아. 무부하 정답률이 높아서, 전체 데이터를 합친 정확 분류율은 오히려 **77.55%**야. 그래서 위치 성능과 부하 판별 성능을 따로 보고하는 게 좋아.

논문에는 다음 정도로 설명하면 처음 읽는 사람도 이해하기 쉬워.

> 실측 힘을 기준으로 유부하와 무부하 구간을 구분하고, 접촉 위치 추정 방식과 무부하를 포함한 분류 방식을 비교하였다. 실제 유부하 구간에서 Masked 모델의 정확 ID 일치율은 66.40%였으며, ±2 및 ±3 segment를 허용했을 때 각각 88.67%, 92.48%였다. Class0 모델은 같은 구간에서 각각 53.91%, 72.53%, 74.50%의 성공률을 보였다. Class0의 유부하 검출률은 77.58%, 무부하 정답률은 94.85%로, 실제 접촉의 검출 누락이 전체 위치 추정 성능을 제한하였다.

이때 **body 결과는 동일 녹화에서 분리한 평가 구간의 성능**이라고 밝혀야 해. ±3에서 92.48%라는 결과를 독립 실험의 접촉 검출률이나 전체 시스템 정확도 92.48%로 표현하면 안 돼.

정리일: **2026-10-14**. 연구자가 설명한 실제 실험 과정과 연구 의도, 저장 코드·결과로 확인한 실행 범위를 구분하여 정리했다. 이 부록은 새로운 학습이나 제어 실험을 수행했다는 기록이 아니다.

### G.1 힘 추정은 끝단 ID18 전용인가, 각 contact ID의 힘인가?

**물리적 정답은 contact ID 위치에 작용한 외력이다.** ID5의 실측 힘은 body ID5의 힘이며, ID18의 실측 힘은 tip 힘이다. 힘 성분은 hrm_base 좌표계로 표현한다. 연구자는 접촉점 외력과 위치를 추정하고, detection mode를 끈 제어에서는 tip 힘으로 취급하거나 ID18로 판단한 경우에만 제어용 힘을 갱신하는 운용을 고려하고 있다.

그러나 **현재 보고한 여섯 실행의 힘 네트워크는 force_scope=tip으로 ID18 데이터만 학습했다.** 위치 네트워크는 ID1–18을 학습했다. 따라서 완료된 결과는 끝단 힘 회귀와 전체 ID 위치 분류이며, 전체 접촉점의 힘을 학습하고 제어에서만 끝단으로 제한한 실험은 아니다. Body 힘까지 검증한 것으로 현재 결과를 확대 해석하지 않는다. 관련 본문: 2.1–2.3절.

### G.2 D405로 형상을 얻고 상대각18개를 만드는 과정은?

연구자 설명에 따르면 D405는 HRM의 비스듬한 상단 약45°에 배치했다. 영상 처리는 **image → binary → skeleton → extrapolation → curve fitting → segment 수에 따른 구간 분할 → 해당 지점의 접선벡터 → segment 각도** 순서다. 카메라와 HRM base 사이의 좌표변환을 사용하여 형상·각도를 hrm_base에서 표현한다. 기록된 카메라 입력에는 RGB에 정렬된 depth와 CameraInfo가 포함된다.

저장 상대각은 base→tip 순서의18개이며 홀수tilt·짝수pan, 단위rad다. Snapshot에는 고정proximal을 포함한19링크/18교대관절이 기록되어 있다. Depth 역투영을 적용하는 정확한 단계, 곡선 차수·피팅식, 상대각 계산식과 접촉ID별 실제 부착점 도식은 별도 확인이 필요하다. 설치각45°만으로 전체 좌표변환이 정해진다고 가정하지 않는다. 관련 본문: 4.1·4.5절.

### G.3 Estimated tip pose와 FK tip pose의 차이는?

연구자가 설명한 비교 의도는 **곡선에서 직접 구성한 끝단 자세와 상대각을 기구학 chain으로 재구성한 끝단 자세의 비교**다.

| 입력 | 연구자가 설명한 의미 |
| --- | --- |
| Estimated tip pose | 영상으로 복원한 곡선의 점과 국소 방향으로 얻은 끝단 자세 |
| FK tip pose | 추정 상대각을 pan–tilt 반복구조의 이론적 기구학 chain에 넣어 구한 끝단 자세 |

학습에는 hrm_base의XYZ와quaternion xyzw를 사용했다. 다만 당시 메타데이터에는 Estimated XYZ가 길이보정fitted boundary, Estimated quaternion이 마지막 링크의filtered DH orientation이라고 기록되어 있어, 기구학에 의존하지 않는 곡선 자세라는 설명과 실제 저장 회전의 관계는 추가 확인이 필요하다. 연구자 설명에 등장하는 접선·법선 중 어느 벡터로 각 자세축을 정하고 roll을 구성하는지도 명시해야 한다. 생성 구현을 확인하기 전 두 표현을 완전히 독립된 센서나 모두 기구학 비의존 자세라고 단정하지 않는다. 관련 본문: 4.1절.

### G.4 실제3D 실험, 외력 인가 장치, 힘 좌표변환과 left/right의 의미는?

연구자는 이번 수집이3차원 실험이라고 확인했다. 각ID에 탄성케이블을 연결하고, 반대쪽을 기존2D 연구에서 사용한 동일F/T센서에 연결하여 외력을 측정했다. 센서의 자세를 유지하면서 위치를 옮겼으며, 센서축과hrm_base축의 방향을 교정해 F_base=R_base_sensor F_sensor로 힘 성분을 표현했다. Left/right는 HRM의 왼쪽/오른쪽에서 힘을 가한 기록을 구분하는 이름이며 추가 분류 라벨이 아니다.

학습 정답은fts_kalman.aligned_fx/fy/fz다. 대표 세션의pan/tilt sine 설정과실행진단도 남아 있다. 각 시점의 공간형상·힘방향 분포, 센서 사양·수집 반복 횟수 등의 정량 프로토콜은 별도로 정리해야 한다. 기록별 실제 축 변환은4.5절의frozen snapshot을 따른다.

### G.5 무부하 경계는 raw 데이터의 표준편차로 구했는가?

연구자는 **약5분간 무부하raw 신호를 필터 없이 측정하고 비정상적인 이상치를 제외한 뒤 표준편차로 범위를 정했다**고 설명했다. 이는 연구자가 수행한 센서 측정 절차다.

반면 **현재 적용 숫자의 저장 계산 이력은Kalman-aligned 신호**를 사용한다. 앞1,957행의평균·표준편차로 정규화한3축 최대편차의95%분위수에1.1을 곱해 축별 반폭을 구했고, 현재는 이를 반올림한Fx±134.326/Fy±126.814/Fz±192.670mN를0중심 수동 경계로CSV에 직접 적용한다. 세 축 모두 경계 포함 범위 안이면 무부하이고 한 축이라도 밖이면 유부하다. 현재 학습에서 평균 차감이나 추가10%확대는 하지 않는다.

Raw 측정 설명과 이 숫자의 산출 이력을 동일한 절차로 서술하지 않는다. Raw 교정의표준편차 배수·이상치 제외 기준·현재 수동값과의 연결은 추가 확인 사항이다. 관련 본문: 6.1절.

### G.6 실시간 접촉 검출과 Class0/Masked 선택은 어디까지 구현됐는가?

연구자 보고에 따르면 제어측은 현재 Class0 방식으로 구현되어 있으며, 이후 Class0/Masked를 선택할 수 있게 할 계획이다. 외부 제어 코드와 실행은 이 저장소에서 검증하지 않았다. 운용 의도는 세 축 모두 지정 범위 안이면 무부하로 보고, 유부하일 때 위치 추정을 활용하는 것이다. 이때 문턱에 넣는 힘이 실측인지 추정인지, 외부 gate와 Class0의 ID0이 충돌할 때의 처리는 명시가 필요하다. 추정 힘을 쓰면 힘 추론 후 문턱을 적용한다.

Class0는 최종 ID0으로 무부하를 나타내며, Masked는 ID1–18만 출력해 자체 무부하 검출이 없다. **Class0가 조금 더 높았다는 결과는 ID0을 제외한 위치 후보의 ±2·±3 채점에 한한다.** 케이블+장력+각도 입력, 위치 Transformer/힘 파트너 MLP의 동일 GT 유부하 body 8,242행 결과는 다음과 같다. Body 평가는 같은 녹화의 분리 구간이다.

| 평가한 출력 | 정확ID | ±2 성공률 | ±3 성공률 |
| --- | ---: | ---: | ---: |
| Masked ID1–18 출력 | 66.40% | 88.67% | 92.48% |
| Class0의ID0 제외 위치 후보 | 64.91% | 89.10% | 92.96% |
| Class0의최종ID0–18 출력; ID0은실패 | 53.91% | 72.53% | 74.50% |

세 행 모두 GT 유부하가 분모이며, 두 번째 행은 모델이 유부하로 검출한 행만 고른 평가가 아니다. 무부하 GT를 추가한 평가도 아니다. 이 수치는 softmax 평균 확률이 아닌 허용 거리 내 정답률이다. 별도 gate를 적용한 두 방식의 실시간 성능이 유사하다는 실험 결과는 아직 없다. 관련 본문: 2.3·12·16.3절.

### G.7 유사 내부입력 다섯 사례의 목적과 영상·형상 자료는?

연구자는 별도의 영상·형상을 보유하며 논문 도입의 동기 그림으로 직접 정리할 예정이다. Base부터 tip까지 떨어진 접촉점에서 힘을 가한 시퀀스 중, 케이블 길이·장력이 가까운 시점을 비교해 유사한 내부정보에도 접촉 위치와 외력이 달라질 수 있음을 보여주려는 것이다. 저장소에도 관련 RGB와 bag·각도/TF 수치가 있으나, 연구자가 보유한 전체 영상/형상을 검토한 것은 아니다.

최종 다섯 사례는 ID1·7·10·15·18이다. **0.05 mm/5 g는 검색 척도이며 최종 다섯 사례 모두의 실제 차이가 그 이내인 것은 아니다.** 최대 케이블 차이 0.073328 mm, 장력 차이 9.23 g, 힘 벡터 차이 1,026.70 mN를 함께 표기한다. 전체 시퀀스가 동일한 것이 아니라 그중 선택한 시점들이 가까운 사례다.

“센서 반복 측정 변동”은 같은 물리 상태를 반복 측정할 때의 흔들림을 뜻한다. 현재 사례는 이 변동과 대조한 실험은 아니지만 근접 입력의 연구 동기 그림으로 사용할 수 있다. 완전 동일 입력이나 수학적 비식별성의 증명으로 확대하지 않는다. 원자료 시각 정합을 포함한 상세 주의점은 15절에 기록했다.

### G.8 이번3D 모델의 pose/PID/admittance 실험은 완료됐는가?

연구자 설명상 기존 2D 연구에서는 pose estimation, PID position control, admittance control을 각각 실험하고 결과를 제시했다. **이번에는 D405/3D 모델로 동일한 종류의 실험을 새로 수행할 예정**이다. 기존 2D 결과를 이번 결과로 재사용하는 계획이 아니며, 예정된 3D 실험을 완료로 표기하지 않는다.

별도 AprilTag 형상 4세션의 원자료는 존재하지만 이번 3D 모델의 제어 실험 완료를 증명하는 자료로 사용하지 않는다. 현재 보고한 동일 녹화 body 분할 평가 외의 독립 body 세션 평가 결과는 확인되지 않았다. 관련 본문: 22절.

# 첫 학습 실행의 결정·가정·확인 필요 사항

대상 데이터: `datasets/20260926_f_ext_datasets`. 사용자가 퇴근 중 질문에 답하기
어렵다고 하여, 요청한 학습·예측·비교를 끝까지 진행하기 위해 정한 사항을 남긴다.
사용자의 결정과 구현 과정의 선택을 구분한다. 실제 실행 완료 여부와 측정 성능은
각 날짜별 `results/.../RESULTS.md`, 비교 CSV, 체크포인트 및 로그가 기준이다.

## 사용자 요청으로 확정한 범위

- 우선 끝단 외력 XYZ를 추정한다. `seg-id-18_left`와 `seg-id-18_right_2`를
  개발 데이터로, 별도 녹화 `seg-id-18_right`를 최종 test로 사용한다.
- 끝단 전용 모델은 조건부 ID18을 고정 출력한다. 힘 임계값으로 무부하일 때
  표시 ID는 0이다. 이는 ID18 분류기를 학습했다는 의미가 아니다.
- 이후 ID1~18을 포함한 힘·하중·조건부 위치 모델을 학습하고, 동일한
  `seg-id-18_right` test로 ID18 인식 여부를 확인한다. 이 녹화는 두 단계 모두
  train/validation에서 제외한다.
- 정답은 Kalman의 aligned Fx/Fy/Fz이며 저장된 부호를 보존한다. 추후 HRM
  제어 코드에서 역정규화된 추론 XYZ에 `-1`을 한 번만 적용한다.
- 축별 무부하 범위는 Fx ±45.4 mN, Fy ±43.6 mN, Fz ±72.9 mN이다.
  세 축이 모두 경계 안(`<=`)이면 무부하, 하나라도 벗어나면 유부하로 판정한다.
- 기존 GitHub 모델군을 기반으로 여러 모델을 동일 데이터로 비교하고,
  학습·예측 코드, 일괄 실행 셸, 날짜별 CSV와 결과 보고서를 만든다.
- 원본 데이터 및 이전 로봇 저장소를 수정하거나 로봇을 실행하지 않는다.

## 원본과 맞지 않는 항목의 처리

`seg-id-18_right_2`는 폴더명과 사용자 설명상 끝단 ID18이지만 원본 CSV/메타데이터의
저장 라벨은 ID1이다. 사용자가 이번 요청에서 이 녹화를 끝단 학습 데이터로 직접
지정한 설명을 우선하여 **학습용 ID18 override**를 명시적으로 설정했다. 원본을
수정하지 않았으며 `source_contact_segment_id`와 audit의 `source_id`에는 ID1을
보존한다. `true_id`는 이 override가 적용된 학습·평가용 라벨이다. 실제 케이블이
끝단에 부착된 실험이었는지는 사용자가 돌아온 뒤 확인해야 한다. 만약 ID1 실험이
맞다면 override를 제거하고 끝단 모델을 재학습해야 한다.

일부 summary의 앞부분 제거와 timestamp 열 불일치를 확인하여, 다음 4개 파일은
로컬 로더에서 **각 토픽의 원본 CSV anchor에 대응시킨 시간 복구**를 적용한다.

| 녹화 | 메타데이터 행 수 대비 제거된 앞 행 수 |
|---|---:|
| `seg-id-15_right` | 53 |
| `seg-id-16_right` | 3 |
| `seg-id-17_right` | 30 |
| `seg-id-18_right` | 29 |

복구는 각 행을 해당 토픽 기록과 연결하여 전 행 일치를 검증하는 방식이다.
단순히 일정 시간이나 행 번호를 추정해 더하는 방식으로 복원하지 않는다.
원본 CSV와 메타데이터를 변경하지 않으며, 복구 근거·행 수·원본 hash를 audit에
남긴다. 기록된 정밀도보다 높은 나노초 정밀도를 새로 만들어냈다고 주장하지 않는다.

## 모델군과 평가 해석

기존 구조를 참고해 PyTorch로 적응한 9개 모델 `mlp`, `cnn`, `convmixer`, `resnet`,
`lstm`, `gru`, `tcn`, `transformer`, `kalmannet`와 추가 `small_gru`, `residual_tcn`의
총11개를 비교한다. 과거 TensorFlow 코드나 가중치의 동일 재현은 아니다. CNN 계열은
실제 시간축 convolution을 사용하며 Transformer는 위치 인코딩과 causal mask를
사용한다. `kalmannet`은 기존 KalmanNetLite를 참고한 GRU 기반 회귀기로, 물리적인
Kalman 필터 갱신을 학습하는 모델이라는 뜻은 아니다.

끝단/body 모두 힘 회귀와 보조 하중 head를 학습한다. Body 위치 loss는 **실제 힘
기준 유부하이며 ID1~18이 알려진 표본**에만 적용한다. 무부하가 되어도 원본 실험
ID를 0으로 바꾸지 않는다. 평가에서는 다음을 구분한다.

- 조건부 위치 정확도: 정답이 유부하인 표본에서 classifier의 ID를 비교한다.
- 하중 판정 포함 위치 정확도: 같은 유부하 표본에서 최종 표시 ID를 비교한다.
  힘을 무부하로 오판하면 실패다.
- 전체 출력 ID 정확도: 실제 무부하의 기대 표시 ID0까지 포함한다.
- 연속 힘 오차: 표시용 hard-zero 이전 예측과 보존된 측정값을 비교한다.
- 하중 F1: 예측 힘의 임계값 판정과 측정 힘의 임계값 판정을 비교한다.
  별도 load head F1과 구별한다.

## 아직 확인되지 않았거나 이번에 수행하지 않은 사항

물리적 힘 교정과 센서 영점의 절대 정확도는 독립적으로 검증하지 않았다. 사용자
제공 표준편차는 이번 실험의 기준으로 적용했지만 다른 날·장착·자세에서도 같은
잡음 범위가 된다는 보장은 없다. 경계 안/밖이라는 파생 라벨은 실제 접촉을 별도
센서로 확인한 정답이 아니다.

이번 비교는 Kalman target으로 진행하며 raw target 비교 실험은 포함하지 않는다.
Kalman target과 부드러운 예측 곡선만으로 응답 지연·동적 정확도를 판정하지 않는다.
원본 nearest ±25 ms 정렬은 미래 측정값을 연결했을 가능성이 있어, causal 모델
자체만으로 전체 시스템의 실시간 인과성이 입증되지 않는다.

CPU 지연은 배치1 모델 forward 측정이다. 센서 전달, 데이터 정렬, 윈도우 준비,
필터와 후처리를 포함한 제어 주기 지연은 별도 검증해야 한다. 이번 실험은 오프라인
학습·예측이며 HRM 제어코드 연동이나 실제 로봇 구동을 수행하지 않는다.

## 실행 중 장치 선택

RTX3060에서 batch1024/window30의 합성 forward+backward를 측정했을 때,
TCN은 CPU4threads 약28ms/CUDA 약623ms, residual_tcn은 CPU 약22ms/CUDA
약744ms였다. cuDNN 해제도 개선되지 않았다. 정확도 결과와 무관한 실행 효율을
근거로 body 단계의 두 모델만 CPU로 지정했다. tip 최초 실행은 CUDA로 진행했다.
모델별 stats.device와 training_seconds를 함께 해석하며 장치가 다른 학습 시간을
같은 하드웨어의 모델 성능 차이처럼 비교하지 않는다.

## 추가 요청에 따른180epoch 및 모델 재사용

초기11모델 비교가 진행 중 사용자가 더 긴 epoch와 학습 모델의 초기 가중치 재사용을
요청했다. 검증으로 선택한 tipMLP를 기준으로 추가180epoch, learning rate1e-4,
patience181을 별도 tip_extended 폴더에서 실행했다. LR scheduler는 기존 정책을
유지했고, test를 보며 모델/설정을 정하지 않았다. 초기epoch0를 포함한181개 평가
행 중 validation최상은 epoch0였으므로 부모 가중치를 유지했다. 이는 새 데이터 추가
효과의 검증이 아니라 같은 개발 데이터에서 epoch를 늘린 실험이다.

향후 warm-start는 현재 config에 적힌 데이터만 사용하며 부모 scaler를 고정한다.
새 optimizer로 시작하고 부모모델의 optimizer상태를 이어받는 재개 기능은 아니다.
옛 개발 데이터를 함께 config에 포함하는 것은 사용자의 데이터 선택 사항이며 자동
재생하지 않는다. 이전 test를 학습에 포함하거나 이전 학습자료를 새로운 독립 test로
지정하는 경우에는 실행을 거부한다.

## 2026-09-27 사용자 라벨 수정 확인

사용자가 right_2의 CSV ID를18로 변경했다고 확인했다. 이전 학습은 이미 명시적
ID18 override를 적용했으므로 이 수정으로 학습용 위치 정답이 바뀐 것은 아니다.
CSV 저장 과정에서 숫자 표기도 달라졌고 session/manifest/schema의 역사적ID1은
남아 있다. 당시 데이터의 정확한 재평가는 토픽CSV로 복원한 summary를 사용했다.
복원 SHA-256은 기존 학습 파일과 바이트 단위로 일치하며, 현재 사용자 CSV는
변경하지 않았다. 선택한26입력+XYZ의 최대 수치차는 약6.3e-13이다.
재평가용 경로는 results/20260926_tip_body_v1/data_replay이며 증거는
data_replay_audit.json에 있다. 과거 checkpoint를 재평가할 때 --data-root로
이 경로를 지정하면 기존 데이터 해시 검사를 유지할 수 있다. 미래 신규학습에서는
CSV와 역사적메타데이터의 라벨 불일치를 명시적으로 정리해야 한다.

## 2026-09-27 front 추가 학습

- 기존tip11개 모델을 신규front1/2/3만으로 추가 학습한다. 사용자 전체ID18 선언이 근거다.
- front_1 CSV18/metadata0 예외는 config에 정확한session/hash와 함께 기록하며 원본 보존.
- front_1 source timestamp 지수표기 반올림은 원본각도기록과 최대5.244µs 차이이며,
  모든6048행×18각도 및 윈도우/분할 동등성을 감사했다. 원래ns정밀도라 주장하지 않는다.
- 각녹화80/20시간validation+양쪽2초purge를 재사용한다. 독립녹화validation은 아니다.
  testset은 별도2601행 녹화이며30sample 윈도우에서2572개 평가시점이다.
- 부모scaler동결, 새optimizer, lr1e-4, 추가180epoch. 과거학습데이터는 replay하지 않는다.
  신규데이터 적응이 과거데이터 성능을 보장하지 않는다. test는 선택/튜닝에서 제외한다.
- maxepoch등은 결과를 보기 전에 정했고, 모델/epoch는validation_loss로 선택한다.
